# 飞书联动

## 一句话

飞书里给机器人发一句话，就在 TidyWork 工作区开一条会话把事办了，结果回飞书；待办和会议到点主动推到飞书。

```
飞书 App（手机/桌面）
   │  文字消息 / @机器人
   ▼
飞书开放平台  ── 长连接（WebSocket，无需公网 IP）──▶  DSH 宿主进程里的 TidyWork 插件
                                                        ├─ ctx.sessionController：建会话 / 提问 / 等回复
                                                        ├─ todos.json / meetings.json：早报、会前、到期提醒
                                                        └─ 回消息 / 发提醒 → 飞书
```

- 不另起服务、不开端口：长连接由插件主动外连飞书。
- 会话真落在 TidyWork 工作区，侧边栏能看到、能继续聊。
- 凭据只写数据目录 `<profile>/tidywork/feishu/config.json`（600），不进安装包、不随导出外发。

## 飞书侧（一次性配置）

1. 打开 [飞书开发者后台](https://open.feishu.cn/app) → 创建「企业自建应用」，名字随意（例如 TidyWork）。需要企业管理员或应用创建权限。
2. **添加应用能力 → 机器人**。
3. **权限管理**开通：
   - 获取与发送单聊、群组消息（`im:message`）
   - 以应用身份发消息（`im:message:send_as_bot`）
   - 可选：获取群组信息（`im:chat`）
4. **事件与回调 → 事件订阅**：添加「接收消息」事件 `im.message.receive_v1`，订阅方式选 **长连接**（不要选 Webhook）。
5. **版本管理与发布**：创建版本 → 申请发布 → 管理员审核通过，应用才真正可用。
6. 在「凭证与基础信息」页复制 **App ID**（`cli_` 开头）和 **App Secret**。
7. 在飞书里搜索应用名，单聊发一句话；要用群就把机器人拉进群，之后 **@它** 才响应。

> 顺序别乱：先开权限和长连接事件，再发布版本。发布前改的权限不会生效。

## TidyWork 侧

工作台顶栏点「飞书」按钮：

1. 填 App ID / App Secret → **保存并连接**。状态会从「未配置」→「连接中」→「已连接（机器人名）」。
2. **发测试消息**：给最近发过消息的私聊/群推一条卡片，验证推送链路。
3. **本地测试问答**：不经过飞书，直接走「建会话 → 提问 → 取回复」，用来验证会话链路；成功说明只剩飞书网络这一层。
4. 提醒开关与时间：
   - 早报时间（默认 08:30）：当天会议 + 今天到期/逾期待办
   - 待办提醒时间（默认 09:00）：只推今天到期和逾期
   - 会前提前分钟（默认 15）：会议开始前推送
   - 免打扰起止（默认 22:00–08:00）：该区间内不发任何提醒

没有凭据时这块只显示「未配置」，插件其它功能不受影响。

## 机制说明

- **会话归属**：每个飞书私聊、每个群里的每个人，各自对应一条 TidyWork 会话，标题形如「飞书 · 私聊」「飞书 · 群 1a2b3c」。同一聊天继续发消息会复用同一条会话，上下文连续。
- **群里 @ 才答**：默认开启，可在弹窗里关掉。群消息不带 @ 会被忽略。
- **白名单**：默认不限；填了 open_id 后只答这些人（被拒时会回显你的 open_id 方便登记）。
- **回复形式**：优先发富文本卡片；卡片失败自动退回纯文本；超过 3000 字自动分片。
- **等待策略**：私聊 6 秒没出结果先回一句「在处理」，整轮最多等 2 分钟；超时会提示去 TidyWork 会话里看。
- **提醒目标**：发过消息的私聊/群自动登记为推送目标（最多 20 个）。
- **去重**：早报、待办、每场会前提醒都按天记账，不会重复轰炸。

## 边界

- **DSH 桌面版必须开着**。桥在宿主进程里，应用退出就没有问答和提醒。
- 提醒精度约 ±30 秒；机器休眠期间错过的早报不补发。
- 群聊里多人各自独立会话，不共享上下文。
- 大文件、图片、语音暂不处理，只认文字。

## 排查

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| 状态显示 invalid-app-id | App ID 复制错 | 应是 `cli_` + 16 位十六进制 |
| 状态卡在「连接中」，25 秒后变成「连接失败」并给出飞书返回的原因 | 凭据不对，或应用没发布 | 按括号里飞书返回的 code 处理：10014 = App ID 不存在，10003/403 = Secret 错或权限没批 |
| 连接失败，提示权限/403 | 应用没发布，或权限没批 | 回开发者后台走完发布审批 |
| 私聊发消息没反应 | 事件订阅没选「长连接」 | 事件订阅页改成长连接后重新发布 |
| 群里 @ 了没反应 | 机器人不在群 / 没 @ / 群里没开 | 拉进群，@ 它；或关掉「群里必须 @」 |
| 能收不能回 | 少了发消息权限 | 补 `im:message:send_as_bot` 并重新发布 |
| 测试消息发不出 | 还没有推送目标 | 先在飞书给机器人发一句话 |
| 提醒不来 | 没开提醒 / 在免打扰 / 应用没运行 | 逐项检查，注意免打扰默认 22:00–08:00 |
