## 二、问题清单与修复方案

### P1-1 超范围会议：块重叠遮挡 + 溢出卡片（T2.2/T2.6）

**现象**（`screenshots/bug-timeline-overlap.png`、`bug-timeline-overflow.png`）
- 时间轴固定 09:00–18:00，对范围外的会议只做了 `Math.max/min` 钳制：
  - 08:00 的会议被画在 09:00 位置，与 09:30 的会议块上下叠在一起，后者的标题被压住看不清；
  - 19:00 的会议块算出 top=292、height=46，超出时间轴 288px 高度，**直接画到了"待办"卡片区域上**，盖住了待办卡标题与视图切换条；
  - 空档文案同时变成「可专注 10:30–**19:00**」，超出卡片标称的 18:00。

**根因**：`renderTimeline` 里 clamp 只夹了起点/终点，没有夹高度，也没有扩展视图范围；空档计算用的是原始 `end`。

**修复方案（F1）**
1. 视图范围自适应：`rangeStart = min(9, floor(当日最早会议开始))`，`rangeEnd = max(18, ceil(当日最晚会议结束))`；只在有超范围会议时扩展，常规日保持 09:00–18:00。
2. 卡头 meta 显示实际范围（例：`08:00 – 20:00`），并在有超范围会议时于卡头加一枚小标签「含 2 场超出 09:00–18:00」，让扩展有解释。
3. 块几何改为：`top = (start - rangeStart) * H`，`height = (end - start) * H - 4`，最小 26px；不再用固定 46px 兜底。
4. 空档计算同时按 `rangeStart/rangeEnd` 裁剪，文案不会越界。

### P1-2 会议块高度失真（T2.2）

**现象**：1 小时会议用固定最小 46px，而真实时长在该尺度下只有 32px，块底边越过下一个整点刻度（09:30–10:30 的块视觉上顶到 11:00），半小时会议同样占 46px。密集日程会互相压住。

**修复方案（F2，与 F1 合并实施）**
- 块高按真实时长计算，最小 26px；块内文字做两级降级：高度 ≥ 34px 显示「时间 + 标题」两行，否则只显示一行「时间 标题」。
- 同一时间段内若会议重叠（并行会议），按开始时间左右分栏（各占 48%），不再上下叠。

### P1-3 接口失败静默成空数据（T10.1）

**现象**（`screenshots/bug-api-500-silent.png`）：把数据文件写坏让 `/tidywork-api/todos` 返回 500 后，页面显示「0 项待办未完成 / 0% / 这个视图里还没有待办」，**控制台只有 500 报错、界面没有任何提示**。用户会以为待办被清空。

**根因**：`reload()` 里四个请求全部 `.catch(() => [])`，把失败当成"没有数据"。

**修复方案（F3）**
- 为待办/会议/笔记各引入 `loadError` 状态；失败时：① 保留上一次成功的数据不清空；② 在工作台顶部显示一条警示条「待办数据加载失败 · 重试」，点击重试；③ 首次加载即失败时，卡片内显示「加载失败，点击重试」而不是"暂无数据"。

### P2-4 笔记时间文案跨天失效（T6.3）

**现象**：`notes.json` 里的 `updatedAt` 存的是「今天 11:30 / 昨天 18:00」这类静态字符串，跨天后仍原样显示——11-09 的工作台把 11-08 编辑的笔记标成「今天 11:30」，笔记面板也写「最后编辑：今天 11:30」。

**修复方案（F4）**
- 数据层：`updatedAt` 改存 ISO 时间（`2026-11-08T11:30:00+08:00`），服务端写入时自动生成。
- 展示层：新增 `relTime(iso)` → 今天/昨天/前天/M月D日，兼容旧数据（非 ISO 字符串原样显示，不报错）。
- 迁移：读取时若遇旧字符串，按笔记顺序不猜测日期，保留原样并在下一次保存时覆盖为 ISO。

### P2-5 零待办时结论句错误（T4.2）

**现象**（`screenshots/edge-zero-todo.png`）：0 条待办时显示「待办全部完成，今天可以收尾了。」——事实上一件事都没有。

**修复方案（F5）**：`total===0` → 「还没有待办，先加一条吧」；`open===0 && total>0` → 保留现文案；其余不变。

### P2-6 无会议时两条重复提示（T2.5）

**现象**（`screenshots/edge-no-meeting.png`）：空态同时显示「今天没有安排，适合安排一段深度工作。」与「可专注 09:00–18:00」，同一件事说了两遍，且一个贴在顶部、一个浮在中间。

**修复方案（F6）**：无会议时只保留一条居中提示「今天没有会议，整段可专注 09:00–18:00」；有会议时维持现有空档标注。

### P2-7 长标题未按设计单行截断（T3.8）

**现象**：40+ 字的标题在行内换行成 2 行，行高从 32 撑到约 50，列表节奏被打乱（设计口径是单行省略号）。

**修复方案（F7）**：标题 span 补 `whiteSpace:"nowrap"` + `minWidth:0`；父级已 `overflow:hidden`，即可单行省略，悬停用 title 属性显示全文。

### P2-8 撤销/勾选热区偏小（T3.3/T3.4）

**现象**：勾选框 18×18px、toast 里「撤销」文字热区实测 **26×18.5px**，触控与手滑场景容易点不中（第一次实测就没点中，需按 DOM 坐标精确点击才成功）。

**修复方案（F8）**：勾选框外层加 8px 内边距（视觉尺寸不变、热区到 34×34）；toast 的撤销改为带 `padding: 6px 12px` 的按钮，热区 ≥ 44×32。

### 附：待确认项（非本次引入，建议一并处理）

- **「本周」同名不同义**：工作台「本周」= 本周一至周日区间内到期的待办（当前 4 条）；待办面板「本周」= 服务端 `view=week`，实际规则是「due 为 today 或 tomorrow」（页面显示 10）。两处同名但含义不同。
  建议：把待办面板该视图改名为「近日」（today+tomorrow 的语义），工作台保持「本周」。
- **时间轴无"当前时刻"指示线**：今天 09:00–18:00 之间没有当前时间标记，看不出"现在处在哪"。建议加一条 1px 时间游标（仅今天显示）。
