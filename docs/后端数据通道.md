# TidyWork 后端数据通道（给排查用）

## 一句话

插件不是一个独立服务，而是**挂在 DSH 宿主进程里的一个 Cordis 插件**：它把 `/tidywork-api` 路由注册到宿主自己的 `webServer`，数据落在宿主 profile 的 `tidywork/` 目录。**哪个 DSH 实例加载了插件，接口和数据就在哪个实例上。**

## 进程与路由

```
DSH 宿主进程（桌面 App 或容器里的 dsh）
├─ webServer  ← 插件用 ctx.webServer.register({kind:"prefix", path:"/tidywork-api"}) 挂上去
│    └─ /tidywork-api/{todos,meetings,notes,...}
├─ tools     ← 插件注册 tidywork_add_todo / _meeting / _note（会话工具）
├─ systemPrompt ← 插件注入 tidywork:workspace 段落（告诉模型怎么写数据）
└─ client（浏览器/渲染进程）→ 面板 fetch 同源 /tidywork-api
```

- 路由处理在 `lib/index.js` 的 `apply()` + `handle()`：GET 直读，写请求按资源（todos/meetings/notes）串行排队。
- 存储是纯 JSON，路径 `dataRoot()` = `<profile>/tidywork/{todos,meetings,notes}.json`；写入先写临时文件再 rename，避免读半截；笔记另有 `rev` + 历史版本，冲突返回 409。
- 桌面端 profile 是 `~/.dsh/profiles/desktop`，所以数据在 `~/.dsh/profiles/desktop/tidywork/`。
- 面板（`lib/client.js`）和接口同源，所以面板永远读当前实例的数据。

## 为什么会出现「写进了容器的 3080，客户端看不到」

本机同时跑着两套 DSH：

| 实例 | 地址 | 数据目录 |
| --- | --- | --- |
| 桌面 App（用户看到的窗口） | `127.0.0.1:<随机端口>`（每次启动都变，用 `ctx.webServer.getOrigin()` 取） | `~/.dsh/profiles/desktop/tidywork` |
| 容器部署 tidywork-assistant | 容器内 `:3080`（宿主机也映射 3080） | 容器里 `/root/.dsh/profiles/web/tidywork`（挂在项目 `data/dsh/...`） |

旧版系统提示把接口地址写死成 `http://$(hostname -I):3080`。桌面端会话里的 bash 是在宿主机上跑的，请求打到 `127.0.0.1:3080`，正好落在**容器那套**实例上：数据写进了容器的 profile，桌面端的 `/tidywork-api` 读的是另一个文件，于是面板显示 0 条。

## 现在的写入方式（本次修复后）

`apply()` 时用 `ctx.webServer.getOrigin()` 把本实例真实地址写到：

- `~/.dsh/profiles/desktop/tidywork/api-endpoint.txt` —— 一行 `http://127.0.0.1:<端口>`
- `~/.dsh/profiles/desktop/tidywork/tw` —— 薄封装脚本：`sh tw <METHOD> <PATH> [JSON]`，自己读上面的地址再 curl

系统提示改成「先读 `api-endpoint.txt`，再用 `tw` 脚本」，并明确写了「不要写死 3080」。这样无论插件跑在桌面端还是容器里，写到的都是**当前实例**。

排查命令：

```sh
cat ~/.dsh/profiles/desktop/tidywork/api-endpoint.txt
sh ~/.dsh/profiles/desktop/tidywork/tw GET /meetings?month=2026-11
```

## macOS 桌面端布局约定（顶栏让位）

收起侧边栏时，DSH 把「打开侧边栏 / 新建会话」浮在主面板左上角，并在 frame 上发布 `--dsh-frame-leading-clearance`；根元素始终发布 `--dsh-frame-top-clearance`（48px）。入口型主面板要用它做顶部内边距，否则顶栏会压在浮层控件下面（看起来像标题被画了两遍）。

插件里的做法：三个列表页根节点带 `.tw-frame-page`，CSS 注入 `padding-top:var(--dsh-frame-top-clearance,0px)`；工作台顶栏把这条带算进自己的 `padding-top`，并保留 `data-window-drag` 让整条仍是可拖区域。
