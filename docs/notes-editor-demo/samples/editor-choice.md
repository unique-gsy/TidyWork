# 笔记编辑器选型：Vditor 试点

## 背景

现有笔记正文是「Markdown 真源 + 字符串拼 HTML」的极简渲染，写态靠 `textarea`，即时模式按块重复渲染。
问题集中在长文性能、表格编辑、输入法三处。

## 结论

用 `Vditor` 的 **ir（即时渲染）** 模式做试点，只保留单主题、隐藏工具栏，外壳仍用 TidyWork 自己的列表与状态栏。

## 结构

```js
// 只依赖 ir 模式需要的四类资源，其余按需加载
{
  cdn: "./vendor/vditor",       // 本地托管，不走公网
  mode: "ir",                   // 光标行露源码，其余渲染
  toolbar: [],                  // Typora 没有工具栏
  cache: { enable: false },     // 草稿自己管，别和本地存储打架
  theme: "classic"
}
```

## 体积预算

| 资源 | 大小 | 是否必需 |
| --- | --- | --- |
| index.min.js | 290KB | 必需 |
| index.css | 47KB | 必需 |
| lute（Markdown 引擎） | 3.7MB | 必需 |
| katex | 1.5MB | 公式要才装 |
| highlight.js | 1.0MB | 代码要高亮才装 |

## 验收口径

- 1.1 万字笔记，输入延迟 < 30ms
- 中文组字期间不跳字、不丢光标
- 表格 Tab 走格、Enter 换行、行内增删行
- 专注 / 打字机两个开关可关可开，关掉后滚动行为与现在一致
- 单主题：不出现 Vditor 自带的第二套皮肤

## 一个数学公式的例子

渲染延迟期望按文档长度近似估算：

$$
T(n) \approx \alpha \cdot n + \beta
$$

其中 $n$ 为块数，$\alpha$ 为单块重排成本，$\beta$ 为固定开销。块级渲染的意义就是把 $\alpha$ 压到常数级，而不是随 $n$ 增长。
