# TidyWork 插件 · DSH 桌面版安装包（v3.40.0）

给已经装好 **DeepSeek Harness 桌面版** 的人用：装完侧边栏会多出 **工作台 / 待办 / 会议 / 笔记** 四块，工作台一屏看今天的日程与待办。

**v3.32–v3.33 把邮箱接进了界面与插件设置**（后端的邮箱引擎在 v3.31 已并入）：

- **顶栏只有一个按钮**：没配邮箱时显示「配置邮箱」，点开就是设置弹窗；配好之后按钮变成「扫描邮箱」，点一次直接扫。授权码失效时点扫描会自动把设置弹窗带出来并说明原因。弹窗里的账号框默认是空的，想换号或清空可以点「清除已保存的账号」。

- **扫描范围**：近 7 天的邮件 + 日历，抽出的待办和会议直接落到面板里；扫描要几十秒，按钮会显示「扫描中…」。
- **「✉ 邮箱」来源标**：待办和会议里凡是邮件抓来的，都带一个青蓝色小标，鼠标悬停显示邮件主题与发件人；手输的条目没有。
- **会议「接受 / 拒绝」**：邮件邀请类会议（`rsvp = pending`）卡片上直接两键回复，确认后显示「已确认参加」，拒绝的会从看板移出。
- **凭据只在数据目录**：账号与授权码由「邮箱设置」弹窗写入 `~/.dsh/profiles/desktop/tidywork/mail/config.ini`（600 权限），不需要手动编辑文件；插件目录与安装包里只有一个 `config.example.ini` 模板，不会再带着别人的邮箱跑。
- **兼容旧数据**：上一版写下的 `mail_key`、`urgent/normal`、中文 rsvp 标签，首次同步时自动归一，不会重复出现两条。

**v3.30 那一版做的是"安全 + 稳定 + 顺手"的整改**，界面大结构不变：

- **接口不再裸奔**：`/tidywork-api` 所有写操作校验 Host（只认本机或宿主自身域名）、Origin（必须同源）、`Sec-Fetch-Site`（只允许 same-origin/none），并且写请求必须声明 `application/json`。别的网页没法再借你的浏览器改数据（CSRF）。
- **报错说人话**：字段超长、类型不对、找不到、冲突（笔记被 AI 改过）现在都有明确的状态码和提示，不再"静默截断"或一律 500。
- **视图口径统一**：全部/今天/本周/逾期/分类都按"截止日归一成具体日期"来算，切视图不再闪重复行；新增「逾期」视图。
- **会议时间结构化**：改成"开始时间 / 结束时间"两个时间输入，状态按区间自动判（未开始/进行中/已结束），每分钟重算；老数据照旧显示。
- **笔记更省内存**：正文单独存 `notes/<id>.json`，列表只读索引（首次启动自动迁移老数据，不用手动处理）。
- **删除可撤销**：待办、会议、笔记删掉后底部 toast 里有「撤销」，不再弹系统确认框。
- **备份能带走**：工作台顶栏「导出」下载一份完整 JSON（待办 + 会议 + 笔记）。
- **键盘可用**：可点元素都有焦点圈；启动时记住上次停留的面板，不会每次都被弹回工作台。

**脚本按平台分成两套**，用你系统对应的那一套即可，插件本体（`plugin/`）共用：

```
mac-linux/   安装-mac.command  卸载-mac.command   install-mac.sh   uninstall-mac.sh
windows/     安装-windows.bat  卸载-windows.bat   install-windows.ps1  uninstall-windows.ps1
plugin/      插件本体
```

## 前置条件

1. 已安装 `DeepSeek Harness` 桌面版。
2. **至少打开过一次**——它会在自己的配置目录（mac/Linux `~/.dsh/profiles/desktop`，Windows `%USERPROFILE%\.dsh\profiles\desktop`）里生成配置文件，安装脚本要往这里登记插件。
3. 不需要 Node、pnpm，脚本借用应用自带的运行时。

## macOS

双击 `mac-linux/安装-mac.command`。

- 若提示"无法打开，因为无法验证开发者"：右键 → 打开 → 仍要打开。
- 或在终端里：`sh mac-linux/install-mac.sh`

卸载：双击 `mac-linux/卸载-mac.command`（或 `sh mac-linux/uninstall-mac.sh`）。

## Linux

命令行执行：

```bash
sh mac-linux/install-mac.sh
```

脚本会去 `~/Applications/*Harness*.AppImage`、`/opt/DeepSeek Harness/`、`~/.local/bin` 里找应用。找不到就用环境变量指定：

```bash
TW_APP=/path/to/DeepSeekHarness.AppImage sh mac-linux/install-mac.sh
```

卸载同理，换成 `uninstall-mac.sh`。

## Windows

双击 `windows/安装-windows.bat`。

- 会弹出命令行窗口跑脚本，结束后按回车关闭。
- 若 SmartScreen 拦下：点"更多信息 → 仍要运行"。
- 脚本以**当前用户**身份运行，不申请管理员权限（DSH 桌面版本身就是用户级安装）。
- 也可以在 PowerShell 里手动跑：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\windows\install-windows.ps1
```

卸载：双击 `windows/卸载-windows.bat`。

## 飞书机器人（可选，每个人配自己企业的应用）

装好插件后，工作台顶栏会出现「飞书」按钮。飞书这部分**没有全局开关，也不能共用别人建好的机器人**——机器人属于某个企业的飞书租户，凭据也只能由该企业的人创建。所以每个使用者（或每个企业）各建一个应用、各填各的凭据，互不影响。

### 一、在自己的飞书开放平台建应用

1. 用企业账号打开 <https://open.feishu.cn/app>，点**创建企业自建应用**，填名称（例如 `TidyWork 助手`）和描述。没有开发者权限的话，先找企业管理员开通。
2. 进入应用 → **添加应用能力** → 添加**机器人**。
3. **权限管理** → 开通权限，勾选这四个（均为应用身份 / tenant_access_token）：
   - `im:message`（获取与发送单聊、群组消息）
   - `im:message:send_as_bot`（以应用的身份发消息）
   - `im:message.p2p_msg:readonly`（读取用户发给机器人的单聊消息）
   - `im:message.group_at_msg:readonly`（获取群组中用户 @ 机器人消息）
4. **事件与回调** → 事件配置 → 订阅方式选**使用长连接接收事件**并保存；再**添加事件** `im.message.receive_v1`（接收消息）。长连接不需要公网地址，也不用配加密策略。
5. **版本管理与发布** → 创建版本 → 填版本号（如 `1.0.0`）和更新说明 → 可用范围选**部分成员**（把自己加进去）→ 提交。可用范围在 5 人以内时平台**免审核、立即生效**；要全员使用就得改成全体成员并等企业管理员审批。
6. 回到**凭证与基础信息**，复制 **App ID**（`cli_` 开头）和 **App Secret**。

### 二、填进 TidyWork

打开 DSH 桌面版 → 工作台 → 顶栏「飞书」→ 填入 App ID、App Secret → 保存。

- 状态圆点变绿、显示机器人名称，就是长连接通了；没通时 25 秒内会给出飞书返回的具体原因（如 `10014 app id not exists` 表示 App ID 不对）。
- 然后到飞书里搜机器人名字，发一句话测试；群里用的话把它拉进群并 @ 它。
- 提醒（早报 / 待办 / 会前 N 分钟 / 免打扰）在同一个弹窗里改；推送目标不用手填，谁先给机器人发过消息就自动登记（最多 20 个）。
- 凭据只落在本机 `~/.dsh/profiles/desktop/tidywork/feishu/config.json`（600 权限），**安装包里不含任何人的 App ID / Secret**，换机器要重新填一次。

### 三、转手给别人时要注意

- 直接把安装包给对方即可，他按上面第一、二步配自己的应用；不要把你自己的 `feishu/config.json` 一起发出去。
- 两个人同时用两个不同的应用没问题，但**同一个应用不要被两台机器同时开长连接**（飞书允许，但消息会被随机分到其中一个连接，表现为"有时不回"）。
- 机器人回复用的是互动卡片，卡片发送失败会自动退回纯文本；单条超过 3000 字会分片。

## 安装脚本具体做了什么

两套逻辑一致，四件事：

1. 把插件复制到 `~/.dsh/plugins/tidywork-plugin`（固定位置，不留在下载目录，避免被清理后失效）。
2. 再复制一份到 DSH profile 的 `node_modules/@tidywork/dsh-plugin`。
3. 备份 profile 的 `package.json`，再原地追加两处登记：`dependencies` 加 `"@tidywork/dsh-plugin": "file:<第 1 步的路径>"`，`dsh.profile.bundles` 追加 `"@tidywork/dsh-plugin"`。
4. 重启 DSH 桌面版。

全程只碰 `.dsh` 下与 TidyWork 有关的路径，**不修改应用本体**，不需要管理员权限。

> Windows 上脚本按"用户级安装"的默认路径 `%LOCALAPPDATA%\Programs\DeepSeek Harness\` 找应用，找不到再查注册表里的安装位置。

## 常见问题

- **侧栏没出现入口**：确认脚本最后打印了"完成"；彻底退出应用（macOS ⌘Q／Windows 关掉所有窗口与托盘图标）再打开。仍不行就看 profile 的 `package.json`，`dsh.profile.bundles` 里应有 `@tidywork/dsh-plugin`。
- **升级**：用新版包再跑一次安装即可，脚本会先清掉旧的 `lib/`、`locale/`（不留旧版本残留文件），`package.json` 备份只保留最近 3 份。
- **数据在哪**：profile 目录下的 `tidywork/`——`todos.json` / `meetings.json` 是清单，`notes.json` 只是索引，每篇笔记正文在 `notes/<id>.json`，附件在 `attachments/`。整目录拷走就是完整备份，也可以用工作台顶栏「导出」拿一份 JSON。
- **接口自检**：浏览器打开 `http://127.0.0.1:<端口>/tidywork-api/health` 能看到版本与数据目录；端口在 `tidywork/api-endpoint.txt` 里。
- **工作台顶栏「＋ 新建工作项」**：点它回到 TidyWork 工作区里"今天"那个会话（没工作区就建、今天没会话就建），进去直接用自然语言交代待办/会议安排即可。
- **飞书一直显示连接失败**：先看弹窗里的错误码。`403`/权限类 → 权限没批或应用没发布；`10014` → App ID 复制错；能连上但发消息不回 → 少了 `im:message:send_as_bot`。改完权限或事件要**重新发版**才生效。
- **Windows / Linux 未实测**：macOS 上做过完整安装、重复安装、卸载验证；Windows 与 Linux 分支按同样逻辑与各自默认安装路径编写，若首次运行报错，把命令行提示发回即可定位。
